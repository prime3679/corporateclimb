# Review Rules

- Report findings first, ordered by severity, with file and line references when available.
- Prioritize bugs, regressions, privacy or safety risk, deterministic breakage, and missing verification over style notes.
- If there are no findings, say so explicitly and note any residual risk or testing gap.
- Keep one-off judgment in the review itself.
- Turn repeatable defects into tests, lint rules, or CI.
- Turn missing domain knowledge into canonical docs or a reusable skill.
- Turn agent behavior failures into operating evals.
